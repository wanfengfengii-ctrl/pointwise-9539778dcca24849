# snapshots — 持久化 JSON 分支快照库

纯 Python 标准库实现。`snapshots.Store(document)` 以 `document` 为版本 0
创建仓库;`apply(base, ops)` 从任一旧版本派生,依次执行一批操作,全部
成功后返回递增的新版本号;`read(version, path)` 返回该版本 `path` 处的
普通 JSON 值。

```python
import snapshots

store = snapshots.Store([1, 2])          # 版本 0
v1 = store.apply(0, [{"op": "add", "path": ["0"], "value": 9}])
store.read(v1, [])   # [9, 1, 2]
store.read(0, [])    # [1, 2]  版 0 不变
```

## 操作语义

ops 项为 `{"op", "path", "value"}`,`remove` 无 `value`。path 是字符串段
列表,空列表指根;对象段是字段名,数组段是规范非负十进制下标(无前导
零/符号),数组 `add` 允许下标等于长度或 `"-"` 追加。

- `add`:父路径须存在;数组按下标插入,对象设置/覆盖 字段;空路径整体换根。
- `remove`:目标须存在;根不可删除。
- `replace`:目标须存在;根可替换。
- `test`:目标须存在且 JSON 相等;布尔与数字不同(`true != 1`),
  `1` 与 `1.0` 作为数字相等。

批内依次执行;非法版本/路径/操作或 `test` 失败抛 `ValueError`,整批不
新增版本。约束:深度 ≤ 32、对象 ≤ 32 字段、数组 ≤ 200000 项,违反即
`ValueError`。

## 结构共享说明

- 数组用**带子树大小的持久化 AVL 树**:定位/插入/删除/替换每层只复制
  根到目标路径上的 O(log(n+2)) 个节点,其余子树按引用共享,绝不做整
  数组扫描或复制。
- 对象字段 ≤ 32,用**有序键元组**实现,一次更新只复制一条 ≤32 项的
  元组,视为常数级。
- 初始化导入、`read` 导出、`test` 比较按所涉值大小处理(契约允许)。
- 传入值被深拷贝为内部节点,`read` 导出全新 list/dict:修改传入值或
  读取结果不影响任何版本。

## 原子性说明

所有更新都是纯函数:输入当前根、返回新根,不就地修改。`apply` 把整批
操作折叠在基版本的根上,**只有全部成功后才把新根追加进版本表**;任何
失败在追加之前抛出 `ValueError`,因此失败的批不会新增版本,已有版本
全部不受影响。

## 独立参照核验

`verify.py` 内含一个独立的朴素参照模型(深拷贝 + 普通 list/dict,与
`snapshots` 实现无共享代码),用固定种子随机生成文档、版本基与操作批
(含畸形操作),对两侧的成功/报错行为、版本号、全部版本的全文及随机
路径读取结果做差分比对,并白盒校验 AVL 平衡与大小注解。当前核验:
14 项单元测试 + 221 个成功随机批次全部一致。

## 长数组头部插删资源实测

`verify.py` 实测输出(每次 2000 个操作取均值;对照为 `[x] + lst` 整表
复制的朴素做法):

| 数组长度 | 头插 µs/op | 头删 µs/op | 整表复制 µs/op |
|---------:|-----------:|-----------:|---------------:|
|    10000 |       12.4 |        7.2 |           44.4 |
|    50000 |       15.1 |        8.8 |          221.6 |
|   200000 |       56.5 |       21.8 |         1081.5 |

长度放大 20 倍,本库单次操作耗时仅约 4 倍(≈log 增长),而整表复制随
长度线性增长。结构共享实测:对 n=200000 的数组头插 1 次,**新增节点
19 个 / 共 200000 个,共享 199981 个**(log2(n)≈17.6);500 次头插的
峰值内存约 913 KiB(≈1.8 KiB/次),整表复制每次约需 1562 KiB。
